What was already in the build
  No 2nd-user or 2nd-pad support. UserService hardcodes the single configured user_id. The pad
  code has one global Controller (state + 64-entry history) and handle 1 only. That Controller
  already tracks every connected host device (m_connected_ids), but it only accepts input from
  the first non-keyboard one; input from any other device is dropped. --keyboard-player is only
  parsed (the README lists it as unsupported).

What the patch does
  User service (P2 = configured user_id + 1, i.e. 1001 with the default 1000)
    - GetLoginUserIdList returns {1000, 1001, -1, -1}
    - GetEvent returns Login(1000), then Login(1001), then "no event"
    - GetUserName(1001) = "Player 2"; GetUserNumber(1001) = 2
    - GamePresets/AgeLevel/Accessibility* getters accept 1001 as well as 1000
  Pad
    - A second Controller object is created next to the original one at startup.
    - The first gamepad stays player 1 (unchanged code path, including the DualSense features).
      The next gamepad that connects (or the first input from another gamepad) is bound to
      player 2. Its buttons, sticks, triggers, touchpad and motion go into the second Controller.
      The keyboard always stays player 1.
    - PadOpen/PadGetHandle(1001, 0, 0) -> handle 2. PadReadState, PadRead,
      PadGetControllerInformation and PadClose work for handle 2.
    - Unplugging player 2 unbinds it; the next gamepad (re)connected becomes player 2.
  Player 2 output (v2)
    - PadSetVibration, PadSetLightBar, PadSetTriggerEffect, PadGetTriggerEffectState,
      PadSetMotionSensorState and PadResetOrientation for handle 2 act on player 2's controller.
      The other pad calls that only check the handle (PadResetLightBar, PadIsRemoteController,
      PadSetVibrationMode, PadSetTiltCorrectionState, ...) now accept handle 2.
    - The DualSense rumble path of "DualSense features" (dualsense-fix) drives one global
      DualSense session, so it stays on player 1. Player 2's rumble goes through SDL's normal
      per-controller rumble instead. Light bar and adaptive triggers already go through SDL
      per controller.

Known limits
  - Player 2's DualSense speaker is not routed (controller audio is a separate path).
  - The launcher's controller color (Settings > Controller, controller_color) overrides the
    light bar of every controller, so both show that color instead of the game's colors.
  - PadRead for handle 2 returns one sample (the current state), not the queued history.
  - Two users are always logged in, even in single-player modes.
  - If player 1's gamepad disconnects, the remaining gamepad also drives player 1 (upstream
    behaviour of the original Controller).
  - Other libraries (save data, trophies, NP, ...) still only know user 1000. If the game
    calls one of them for 1001 it may get an error, or a hard stop if that HLE asserts.
  - v1 (input + users) was confirmed working in UFC 6 local versus. The v2 output part is
    checked statically (all branch/data targets resolve, every return lands on an original
    instruction boundary, no stray byte changes) and the exe starts, but is not yet tested in game.

Test plan
  1. Close the launcher. The launcher always starts "kyty_emulator.exe", so swap the files
     (in this folder, PowerShell):
        Rename-Item kyty_emulator.exe kyty_emulator_orig.exe
        Copy-Item kyty_emulator_2p.exe kyty_emulator.exe
     Undo:  Remove-Item kyty_emulator.exe; Rename-Item kyty_emulator_orig.exe kyty_emulator.exe
  2. Connect the controller for player 1 first (the DualSense), then the second controller.
     Both connected before you press Start.
  3. Start UFC 6 from the launcher as usual.
     Check: the game boots and the menus work with controller 1 exactly as before.
  4. Go to local versus (Fight Now / Play Now, versus a second player). Press buttons on
     controller 2 when the game asks for player 2.
     Check: a second player joins and is controlled by controller 2 only.
  5. In a fight: move both fighters at the same time.
     Check: each controller moves only its own fighter.
     Check (v2): both controllers vibrate on hits, each only for its own fighter; controller 1's
     rumble never stops or sticks because of controller 2; adaptive triggers resist on both
     DualSenses where the game uses them.
  6. Optional: unplug controller 2 in a menu and plug it back in.
     Check: it controls player 2 again.

  If something goes wrong, tell me which step and what you saw:
    - crash or freeze at boot (before the menus)
    - controller 2 does nothing / the game never offers player 2
    - controller 2 moves player 1
    - crash when player 2 joins or a fight starts (UFC may then be calling another library
      for user 1001; the console window's last lines help, if the emulator shows one)
